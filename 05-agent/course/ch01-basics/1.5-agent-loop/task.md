# 1.5 Agent Loop — 编码练习

## 目标

实现一个完整的 Agent Loop，演示"观察→决策→行动"的多轮循环，包含工具调用、结果回传、终止条件和失败重试。

**不调用真实 LLM**，用规则模拟决策。重点理解循环结构本身。

## 场景

一个"天气出行助手"Agent，用户问"明天适合去公园吗？"，Agent 需要：
1. 调用天气工具查询明天天气
2. 根据天气结果判断是否适合出行
3. 给出最终建议

如果天气工具调用失败，Agent 需要重试（最多 2 次）。

## 步骤引导

### 第 1 步：定义状态（State）

Agent 在循环中需要记住的所有信息。

- 提示：包括用户目标、当前步骤、工具调用历史、最终答案
- 关键点：状态是不可变的，每轮返回新状态（参考 1.4 的 Environment 设计）

### 第 2 步：定义工具（Tools）

Agent 可以调用的外部能力。

- 提示：定义一个天气查询工具，返回天气信息（模拟数据）
- 关键点：工具可能成功也可能失败，需要返回统一格式 `{"success": bool, "data": ...}`
- 额外：模拟一个随机失败的场景，用于测试重试逻辑

### 第 3 步：实现决策函数（decide）

根据当前状态选择下一步：调用工具、给出最终答案、或终止。

- 提示：用 if-else 模拟 LLM 的决策
- 关键点：决策输出有三种类型：
  - `{"type": "tool_call", "tool": "weather", "args": {...}}`
  - `{"type": "final_answer", "answer": "..."}`
  - `{"type": "give_up", "reason": "..."}`

### 第 4 步：实现工具执行（execute_tool）

运行工具并返回结果。

- 提示：根据 tool 名称分发到对应的工具函数
- 关键点：捕获异常，工具失败不应导致整个 Agent 崩溃

### 第 5 步：实现主循环（agent_loop）

串联所有部分，形成完整的 Agent Loop。

- 提示：参考 1.5 笔记中的伪代码结构
- 关键点：
  - 每轮都要打印日志（观察、决策、行动）
  - 终止条件：最终答案 / 最大步数 / 放弃
  - 工具结果写回状态，供下一轮决策使用

## 预期行为

### 场景 1：正常流程
```
[循环 1] 观察: 用户问"明天适合去公园吗？", 无工具结果
[循环 1] 决策: 调用工具 weather(date=tomorrow)
[循环 1] 行动: 天气查询 → 成功: 晴天, 25°C
[循环 2] 观察: 已有天气结果: 晴天, 25°C
[循环 2] 决策: 生成最终答案
[结束] 答案: 明天晴天 25°C，非常适合去公园！共执行 2 轮
```

### 场景 2：工具失败后重试
```
[循环 1] 观察: 用户问"明天适合去公园吗？", 无工具结果
[循环 1] 决策: 调用工具 weather(date=tomorrow)
[循环 1] 行动: 天气查询 → 失败: 服务超时
[循环 2] 观察: 上次工具调用失败, 重试次数 1/2
[循环 2] 决策: 重试调用工具 weather(date=tomorrow)
[循环 2] 行动: 天气查询 → 成功: 小雨, 18°C
[循环 3] 观察: 已有天气结果: 小雨, 18°C
[循环 3] 决策: 生成最终答案
[结束] 答案: 明天有小雨 18°C，建议改天再去。共执行 3 轮
```

### 场景 3：重试耗尽后放弃
```
[循环 1] 决策: 调用工具 weather → 失败
[循环 2] 决策: 重试 weather → 失败
[循环 3] 决策: 重试次数耗尽，放弃
[结束] 放弃: 无法获取天气信息，请稍后再试。共执行 3 轮
```
