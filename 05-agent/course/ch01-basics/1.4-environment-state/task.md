# 1.4 环境、状态、观察与行动 — 编码练习

## 目标

用 Python 实现一个最简单的"订单处理"场景，演示环境-状态-观察-行动的完整循环。

**不使用任何框架，不调用 LLM**，纯手写逻辑，目的是理解四个概念如何串联。

## 场景

一个订单处理 Agent，需要完成以下任务：
1. 检查库存是否充足
2. 如果库存充足 → 扣减库存 → 发送通知
3. 如果库存不足 → 通知用户缺货

## 步骤引导

### 第 1 步：定义环境（Environment）

环境是 Agent 之外的世界。这里的环境包含订单和库存信息。

- 提示：用一个类表示，内部维护订单状态和库存数量
- 关键点：环境提供"查询"和"操作"两类接口，Agent 不能直接修改环境内部数据

### 第 2 步：定义观察（Observation）

观察是 Agent 从环境中获取的信息片段，不是环境的全部。

- 提示：观察函数接收环境，返回 Agent 决策需要的信息
- 关键点：观察**只读**，不改变环境状态

### 第 3 步：定义决策（Decision）

决策根据观察结果选择下一步行动。

- 提示：输入是观察结果，输出是行动名称和参数
- 关键点：决策逻辑要清晰可读（if-else 就够了）

### 第 4 步：定义行动（Action）

行动是对环境的操作，会改变环境状态。

- 提示：调用环境提供的操作接口
- 关键点：行动可能成功也可能失败，需要返回结果

### 第 5 步：串联循环

把观察 → 决策 → 行动串联成一个循环，直到任务完成。

- 提示：每一轮打印日志，观察循环如何推进
- 关键点：需要一个终止条件，避免死循环

## 预期行为

### 场景 1：库存充足
```
[环境] 订单: A1001, 商品: Widget, 需求: 5, 库存: 100
[观察] 订单 A1001 待处理, 需要 Widget x5, 库存 100
[决策] 库存充足 → 扣减库存
[行动] 扣减库存: Widget -5 → 成功, 剩余 95
[观察] 订单 A1001 已扣减库存, 需要发送通知
[决策] 库存已扣减 → 发送通知
[行动] 发送通知: 订单 A1001 已确认 → 成功
[观察] 订单 A1001 已完成
[结束] 任务完成, 共执行 3 轮
```

### 场景 2：库存不足
```
[环境] 订单: A1002, 商品: Gadget, 需求: 50, 库存: 10
[观察] 订单 A1002 待处理, 需要 Gadget x50, 库存 10
[决策] 库存不足 → 通知缺货
[行动] 发送通知: 订单 A1002 缺货 → 成功
[观察] 订单 A1002 已完成
[结束] 任务完成, 共执行 2 轮
```
