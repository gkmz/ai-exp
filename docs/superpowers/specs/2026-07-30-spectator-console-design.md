# 狼人杀观战控制台设计

## 目标

优化 AgentScope 狼人杀演示的控制台观战体验，通过标题、阶段分隔、角色总览和轮次结算减少连续文本带来的阅读压力。同时增加可配置的观战模式，在单人演示与多人共用终端之间平衡信息完整性和身份保密。

## 配置与信息边界

- 增加布尔配置 `SPECTATOR_MODE`，默认关闭，并允许通过 `.env` 开启。
- 观战模式开启时，控制台展示完整角色表及私密行动内容，方便演示和调试。
- 观战模式关闭时，控制台只展示玩家名单、公开消息和已经公开的身份；私密通知仍发送给对应 Agent，但控制台仅显示不含内容的脱敏提示。
- 游戏结束后身份已无保密必要，两种模式都展示最终身份表。
- 保留 `config.py` 中已有但未提交的 DeepSeek 配置改动，不覆盖、不回退；提交时只暂存本需求相关修改。

## 控制台结构

控制台展示由统一的消息模块负责，避免游戏流程中散落手工分隔符。新增以下展示能力：

- 游戏横幅：展示游戏名称、开始或结束状态。
- 阶段区块：展示夜晚行动、白天公布、遗言、讨论、投票、猎人开枪和轮次结算。
- 玩家与角色表：使用固定序号和对齐列展示玩家；未开启观战模式时，开局角色列显示“未公开”。
- 轮次摘要：展示本轮死亡玩家、当前存活玩家和存活人数；无人死亡时明确显示“无人死亡”。
- 空行策略：横幅、阶段和摘要前后统一留白，普通连续发言之间不额外插入空行，避免输出过度松散。

示例：

```text
════════════════════════════════════════
          三国狼人杀 · 角色总览
════════════════════════════════════════
  01. 刘备      村民
  02. 曹操      狼人
  03. 赵云      猎人
────────────────────────────────────────

┌──────────────────────────────────────┐
│ 第 1 夜 · 夜间行动                   │
└──────────────────────────────────────┘

[主持人][私密通知][→狼人阵营] 请确认击杀目标

──────────────── 本轮结算 ────────────────
死亡玩家：曹操
存活玩家：刘备、赵云
当前人数：2
────────────────────────────────────────
```

## 消息标识

保留现有消息协议，并统一以下可见标签：

- `[主持人][公开公告]`：所有玩家可知的主持人信息。
- `[主持人][私密通知][→接收者]`：仅指定玩家或阵营可知的信息。
- `[玩家][公开发言][玩家名]`：讨论、遗言和技能理由等公开发言。
- `[玩家][私密发言][玩家名][→接收者]`：狼人协商等私密发言。
- `[系统][阶段]`：不属于主持人叙事的流程状态。
- `[系统][警告]`：模型调用失败、非法结构化输出等可恢复异常。

非观战模式下，私密消息的控制台格式为 `[发送方][私密消息][→接收者] 内容已隐藏`，不得打印玩家身份、行动目标或技能选择。

## 游戏流程接入

1. 游戏初始化后打印游戏横幅和玩家总览；观战模式决定是否展示真实身份。
2. 每个昼夜、讨论、投票、遗言和猎人技能流程开始前打印阶段区块。
3. 每轮死亡结算完成后打印轮次摘要，数据以实际结算后的存活状态为准。
4. 胜负产生后打印结束横幅、胜利阵营和最终完整身份表。
5. 阶段标题仅负责视觉组织，不进入 Agent 记忆；主持人公告和玩家发言继续按现有公开或私密规则写入 Agent 记忆。

## 异常与兼容

- 布尔配置接受项目现有配置风格支持的真值和假值；非法值在启动阶段给出明确配置错误。
- 表格对中文玩家名使用稳定的简单列间距，不引入新的第三方终端 UI 依赖。
- 空玩家列表、无人死亡和单个存活玩家均应产生可读输出。
- 不改变狼人杀规则、Agent 提示词、消息 metadata 或胜负判断。
- 不依赖终端颜色，保证日志重定向后仍然可读。

## 测试与验收

- 配置测试覆盖默认关闭、显式开启、显式关闭和非法布尔值。
- 控制台测试覆盖横幅、阶段、角色表、隐藏身份、私密消息脱敏和轮次摘要。
- 游戏流程测试确认开局、阶段切换、轮次结算和游戏结束调用正确展示能力。
- README 说明 `SPECTATOR_MODE` 的使用方式、身份泄露风险和消息标识。
- 通过项目的 Pytest、Ruff、格式检查、Pyright、Mypy 和 `compileall` 验证。
