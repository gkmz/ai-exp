# 游戏消息与猎人流程设计

## 目标

统一区分系统状态、主持人公开公告、主持人私密通知、玩家公开发言、玩家私密发言和技能结算；确保公开消息进入相关 Agent 记忆，私密消息只发送给指定 Agent；补全猎人身份公开、最后遗言和死亡触发规则。

## 消息协议

- 控制台统一使用 `[发送方类型][消息类型][发送者或接收者] 内容` 格式。
- 主持人消息携带 `message_type`、`visibility` 和 `recipient` metadata。
- 公开公告发送给所有当前存活 Agent。
- 私密通知只发送给指定玩家或阵营，但仍以 `[私密]` 标记打印到控制台，便于调试。
- 关闭 ReActAgent 默认控制台输出，由游戏层对最终消息进行分类打印，避免工具调用、普通发言和主持人公告混杂。

## 猎人流程

1. 猎人被狼人击杀或被白天放逐时可以发动技能；被女巫毒杀时不能发动。
2. 发动阶段先公开猎人身份，再发表最后遗言。
3. 猎人结构化输出包含遗言、是否开枪、目标和开枪理由。
4. 开枪目标必须是除猎人外的存活玩家。
5. 开枪结果和理由作为公开技能公告发送给所有相关 Agent。
6. 被猎人带走的玩家直接结算死亡，不再获得遗言。

## 边界处理

- 非法或缺失的结构化输出视为放弃开枪，不中断游戏。
- 公开广播和私密通知分别封装，避免调用点遗漏 `observe()`。
- 夜间多人死亡和猎人带人使用去重后的死亡名单结算。
- 保留工作区已有的女巫规则修改，不覆盖无关的 `util.py` 改动。
